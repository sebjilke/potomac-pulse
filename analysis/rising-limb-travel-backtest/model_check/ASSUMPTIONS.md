# Third implementation: readings taken where the plan was unclear

Plan = `analysis/rising-limb-travel-backtest-plan-2026-11-10.md` incl. Deviations D-1 to D-7. Most literal reading taken in each case.

1. Events (D-7 E5). "Positions 1, 10 and 20" = 1-based positions in the t0-ordered list of the 20 rows with `event_row == 1`, `kept == 1`, `event_class == GATE`, `oct == 0`: event ids 11, 30, 51. October = the kept GATE row with `oct == 1`: event 53. Seeded pick indexes these four in t0 order (11, 30, 51, 53); `default_rng(20261112).integers(0, 4)` = 3, so event 53.
2. Window = ticks t0-71 h through tend+24 h inclusive, where t0 and tend are the event file's `event_t0` and `event_tend`.
3. Slot outcome. Production `storePrediction` can return `replaced` (a missed-window pending is overwritten). TICK_SCHEMA column 47 lists only `stored`, `skipped_in_window`, `no_prediction`, so I compare `replaced` as `stored`. No replacement happened inside any of the four windows, so this mapping was never used in a comparison. The rebuild had 11 replacements.
4. A pending is replaceable when `now - due > 2.5 h` (production `isExistingPredictionReplaceable`). A pending that is not yet due also blocks a new store (`skipped_in_window`). That is production behaviour, not an assumption, but it is listed because the slot name suggests otherwise.
5. Missing gauge values reach the model as JS `undefined`/`null`. Tributary fallback uses `q || fallback`, so a 0 reading would also fall back. No 0 appears in the data. Water temperature: `null` when missing. Values <= 0 °C are real readings, not missing.
6. `validationDue` = `new Date(t + travel*3600000)`, which truncates fractional ms (ECMAScript TimeClip/ToIntegerOrInfinity). Confirmed against the snapshot pending records, e.g. 2026-10-09 pending due 1791556317094 ms, identical.
7. Bins that were never written are `buildCorrectionBins` empty objects without `emaMeanError`. Production's DB fallback for a missing bin row adds `emaMeanError: 0`. These two are equivalent for every read: `classifyOutlier` needs count >= 10, and `updateCorrectionBin` seeds the EMA when the pre-count is 0. The in-memory bin is mutated in place, and the prediction at the same tick sees the update, as production's reload after the upsert does.
8. Stale cleanup (> 48 h since `created_at`) runs only after both Little Falls guards pass (plan 4(c)). `created_at` = the tick of the store.
9. Truth: the 2.5 h search = ticks v, v+1, v+2 from the first tick at or after the target (D-1 C2, D-5 H6). The tick offset is `ceil(h - 1e-12)` (TICK_SCHEMA section 5). `riseRate(t)` = `getPoRRiseRateFromHistory` on the primary history at clock t. "Available" for the mask = view value non-blank.
10. Tolerances. Frozen ones (plan section 6): raw 1 cfs, travel 0.01 h, corr (bins) 0.5 cfs, rebuild 1e-6 cfs, slot/validated/flags exact. For the report-only fields I chose: raw_unc, unc, disp 1 cfs; rate, pct 1e-6; truth and tau_ref 1e-9; views 0; text and integer fields exact. Tick-level fields (mask, truth, views) are compared on every arm row.
11. No harness snapshot of another kept event falls inside any of the four replayed windows. The cross-snapshot bin check therefore had nothing to compare (0 cases). The rebuild covers the bins directly.
12. JavaScript `Math.pow`, `Math.log` and `Math.exp` (V8) and the macOS libm used by Python can differ in the last bit. This shows up as differences of about 1e-11 cfs in `corr` and `unc`. It is not tuned away.
