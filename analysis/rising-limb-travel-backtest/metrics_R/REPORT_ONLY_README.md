# rising_limb_report_only_R.csv (report-only; nothing here decides the gate)

Generated by `rising_limb_metrics_R.R` (section 4), after the gate metrics were written. The scoring rules are the same as for the gate (in_scoring == 1, mask == 1 with the D-8 override tick removed, has_pred asserted). The windows come from the label columns, except where a row says otherwise. Values are written at full double precision. Gains, shares and relative changes are fractions; bias is in percentage points; hours are hours.

Columns: `run` (primary, S2, S3, multi; `event` = arm- and run-independent event facts), `item`, `arm`, `subset`, `stat`, `key`, `value`.

| item | what | key |
|---|---|---|
| EVENT_INFO | per kept event (subset = class): `por_onset_lead_h` (t0 minus PoR onset, hours; blank = no PoR onset found in the window, see ASSUMPTIONS R5); `observed_por_lf_lag_h` (lag 0-48 h maximising the correlation of hourly first differences, dLF(s) vs dPoR(s-lag), s in [t0-12 h, t0+36 h], raw unfilled stamps, at least 10 pairs); `lf_led` (1 if PoR(t0) < 0.5 x LF(t0), raw stamps); `por_t0`; `lf_t0`; `peak_lf` | event_id |
| STRATUM_RL | STRATUM-class kept events, RL window: gain, improved, n_events, n_ticks, mae_arm, mae_base (e_unc) | |
| STRATUM_REC | STRATUM-class kept events, REC window: bias_arm, bias_base, d_bias, n_ticks (e_raw) | |
| STRATA_LED | GATE kept events split LF-led / PoR-led: same stats as STRATUM_RL | group |
| STRATA_SEASON | GATE kept events by season of t0 (DJF, MAM, JJA, SON): same stats | season |
| STRATA_PEAK | GATE kept events by peak class (12k-25k, 25k+): same stats | class |
| PER_YEAR_RL | GATE kept events by UTC year of t0: same stats | year |
| TRAVEL_MODELLED | modelled PoR-to-LF travel per GATE event and arm: mean over the scored RL ticks of travel_por_gf + travel_gf_lf. Compare with EVENT_INFO observed_por_lf_lag_h | event_id |
| POR_CREST_TO_LF_CREST | arm B, per GATE event: PoR crest = first argmax of raw PoR over [t0-12 h, tp]; ticks in (PoR crest, tp]: por_crest_to_tp_h, n_ticks, n_b_active, mae_arm (B), mae_base (e_unc) | event_id |
| BRIEF_WINDOW | the brief's literal window [t0, t0+24 h] of the GATE kept events, from the event file: gain (e_unc), n_ticks | |
| EVENT_EQUAL_GAIN | GATE kept, RL: `gain_mean_of_event_mae` = 1 - mean_e MAE_arm,e / mean_e MAE_base,e; `mean_of_event_gains` = mean_e (1 - S_arm,e / S_base,e) | |
| CAP_BIND | share of scored ticks with ceiling_applied == 1, per arm, RL_all and NORMAL | |
| PER_BIN_RL | RL gain (e_unc) by base_flow_bin, with n_ticks | bin |
| PER_BIN_NORMAL | normal-hours rel_change (e_disp) by base_flow_bin, with n_ticks | bin |
| PER_YEAR_NORMAL | normal-hours rel_change (e_disp) by UTC year of the tick, with n_ticks | year |
| EXCLUDED_GATE_RL | excluded GATE-class events (X0-X4), sensitivity: RL windows from the event file (these have no labels), scored and masked ticks only: gain, improved, n_events (events with at least 1 scored tick), n_ticks | |
| NORMAL_MONTH_BOOT | primary only: G4a rel_change with a calendar-month block bootstrap (blocks = UTC year-months of the scored normal ticks; 10,000 resamples of all months with replacement; `set.seed(20261111)`, `sample.int`, row-wise), ci_lo / ci_hi = 2.5 / 97.5 percentiles type 7, n_months. Exempt from cross-language agreement (D-7 E3) | |

S2, S3 and multi: every item above is also computed for those runs (`run` column), and the gate rows for them are in `rising_limb_metrics_R.csv`. The edge sensitivity G4a_edge / G4b_edge (D-8) is in the gate file, not here.

## Report-only items NOT computed, and why
- Bin EMA trajectories for the 12k-25k rising bin (plan s.4): the tick files carry no bin state (only `corr`, the interpolated correction applied at each tick), and the snapshot file is outside my permitted inputs. Not reconstructable without replaying the learning chain.
- P4 fidelity (s.7, base raw vs the 20 logged hard-flag values): its source sits in `analysis/pulse-audit-2026-10/`, which I may not open. It is also not a section 3/4 report-only item.
- A normal-hours month bootstrap for S2, S3 and multi: the plan names it only for normal hours, so I computed it for the primary run only.
- Lookup-failure shares are not repeated here: they are G7e in the gate file. The S1 base vs own horizon gains are G7d in the gate file.
