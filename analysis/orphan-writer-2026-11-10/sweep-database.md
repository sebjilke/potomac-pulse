## What it would take to stop it (NOT done; read-only)
Nothing is writing new data now (all rise inserts 409). It is wasted load plus a latent hazard: if a rise_event row is deleted (e.g. cleanup) it will be re-created within a quarter hour. Options for the owner: cron.unschedule('potomac-learning-job') (or UPDATE cron.job SET active=false), and/or delete edge function potomac-learner. Then delete the 9 rise_event rows plus the stale snapshot/current and metadata/system rows if wanted. Also consider tightening the permissive "Allow public access" policy.
