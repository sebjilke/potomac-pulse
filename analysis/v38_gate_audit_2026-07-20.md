### Check 3 — Harness fidelity design: PASS, with one serious caveat (Defect 1)

- **(a) One-model-call optimization: verified.** In `scheduled-update.js:742-897` the
  `correctionBins` parameter is consumed at exactly one point — the final
  `applyGFCorrection` call (:862). Nothing upstream (travel-time iteration, tributaries,
  PoR-delta, EF power-law, ensemble/skip, flowState) touches it, so
  `porEstimateCFS/rawFinalCFS/efEstimateCFS/flowState/travelTimeGFtoLF` are
  learning-independent and one call serves all 85 configs.
- **(b) Convex math: matches plan §1/E5 exactly** — displayed = (1−a)·(rawFinal −
  interpCorr) + a·((1−W)·porEst + W·efEst), skip inside the SQ branch only, ceiling on the
  combined value, c1n applies full correction at the combined raw, c1f freezes learning at
  prediction-time a > 0.25, c2/c2m reproduce the logistic (incl. the 1000-cfs floor and 50%
  skip).
- **(c) Common mask: verified** in code (flags gate learning only; every claimed due
  validation with valid LF writes a row for all 85 configs) and by exact count
  reconciliation: multi 123,354 preds = 122,976 scored + 16 missedWindow + 352 noLF + 10
  end-pending; single 23,265 = 23,174 + 6 + 84 + 1. Mask is arm-invariant (shared pending
  entries, arm-independent due times).
- **(d) c0Mismatch = 2/123,354: explained, not concerning.** The harness end-applies the
  correction at the *rounded* `rawFinalCFS` while the model uses the unrounded value; at
  the discrete 25k/50k bin steps a ±0.5 rounding flips the bin. I found exactly 4 step-edge
  prediction hours in the whole replay (raw_c0 = 24999/25000/25000/50001, e.g.
  2018-07-28T09Z, 2025-02-10T15Z) — 2 of them evidently crossed with a >1.5 cfs correction
  gap. Scoring is internally consistent across arms, so no bias.
- **Caveat:** the harness on disk was edited *after* the runs (see Defect 1).

### Defects (severity-ranked)

1. **MODERATE — "single mode rerun" claim is contradicted by the artifacts.** Verdict §4
   and plan v3's decision log state the single-mode D-starvation bug was "fixed and rerun;
   single-mode numbers post-fix." On disk: `v38_residuals_single.csv`/
   `v38_summary_single.json` are 13:45:22, the harness fix is 13:52:40, no rerun process
   exists, and the single file's dbarPred coverage is **12.2%** (vs 97.8% multi) — the
   signature of the pre-fix slot-gated starvation. Consequences: the C1-family single-mode
   diagnostics are vacuous (a≈0 almost always, C1≈C0), and the verdict's claim is currently
   false. Verdict-neutral because multi fails decisively and c2/c2m single numbers don't
   use D̄ — but either rerun single mode with the fixed harness or correct the verdict/plan
   text.
2. **MINOR-MODERATE — 07-19 production-fidelity numbers unreproducible.** Replay disp_c0 at
   2026-07-19T23:00Z = 2,744 vs logged 2,901 → Δ157 (marginally outside max(5%,150)); the
   verdict's "Δ80 / Δ215" pair matches nothing I can derive from the artifacts. The other
   two checks reproduce exactly (Δ78, Δ136 — PASS). E3.3's same-bin/same-correction-sign
   sub-checks are unevidenced. The verdict's conservative handling (W8 demoted to
   diagnostic) is the right outcome under Δ157 as well.
3. **MINOR — census precondition failed as written.** Plan §4's "must reproduce the 6
   historical windows" yielded 4/7 flagged days; the 2019 windows are near-misses (shares
   0.463/0.142/0.442 vs 0.50). Honestly documented, windows frozen as pre-registered;
   immaterial to a FAIL.
4. **MINOR — promised report-only metrics never produced:** per-bin recovery (e), duty
   breakouts by season/temp/flow-bin (f), bin-EMA trajectories (g), CI-coverage during
   active hours (h), ceiling bind-rate (i).
5. **LOW (latent) — simplicity-rule bug in `v38_gate_metrics.py`:** the
   `lo <= delta_vs_best <= hi` test compares C2-minus-bestC1 MAE against the CI of
   bestC1-minus-c0 — dimensionally wrong vs E3.6. Dead code this run (no passing cells);
   would misfire on a future PASS. Fix before any reuse.
6. **LOW — LOEO/neighbors implemented leniently:** condition 5 rechecks only condition 1's

7. **PROCESS — plan v3 (the build spec) is untracked in git** and was edited after results
