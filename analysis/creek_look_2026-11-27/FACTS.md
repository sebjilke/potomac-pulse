## 3. What the app does with creeks today

### 3.1 Which creeks enter the estimate, and with what share
- Four gauged creeks are added to the Point of Rocks flow: Monocacy 01643000, Goose Creek 01644000, Broad Run 01644280, Seneca Creek 01645000 (`netlify/functions/scheduled-update.js:349-354`; browser `src/estimation/great-falls.js:329-332`).
- How: `porEstimateCFS = historicPoR.cfs + monocacyFlow + gooseFlow + broadRunFlow + senecaFlow` when a past Point of Rocks reading was found, else `por.q + ...` (server `scheduled-update.js:1006` and `:1028`; browser `great-falls.js:429`, `:460`). The creek terms are the gauges' latest readings, added at full value, not time shifted (the code at `:991-994` takes `monocacy?.q` and so on).
- Share: no share is applied while a gauge reading exists. When a gauge has no reading (`?.q` falsy) the term is `lf.q` times a fixed fraction: `TRIB_FALLBACK = { monocacy: 0.071, goose: 0.030, broadRun: 0.0066, seneca: 0.0087 }` (`src/model/constants.js:131`; server `netlify/functions/shared/model.js:832-837`; "Used only when real-time gauge data is unavailable").
