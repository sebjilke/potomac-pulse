# Potomac Pulse v39.10 plan (client only; estimate unchanged)

Written by the orchestrator on 2026-11-14. Three items the owner approved ("do it") from a list of
customer-experience ideas he asked for. Line numbers are from commit 7c47cac.

## Scope

1. **Rename the gauge-list column label "24h Trend" to "Next 24h".** The value is a forecast (the
   National Weather Service flow 24 hours ahead against the flow now), so the old name read like
   history. The explanation text stays exactly `Forecast change in flow over the next 24 hours`.
2. **The whole column label opens the explanation, not only the 13 px "i".** A tap or click anywhere
   on the "Next 24h" or "Basin" header cell toggles that cell's bubble.
3. **Stop requesting the flood stage nobody shows.** Since v39.9 removed the map, nothing reads
   `data[id].floodCategory`. `fetchNWSForecasts()` still makes one request per National Weather
   Service gauge (17 gauges) to `https://api.water.noaa.gov/nwps/v1/gauges/{lid}` on every refresh,
   each with a 5 s timeout. Remove those requests. Remove the dead export `getTrendText` from
   `src/data/fetch.js` as well (TODO C7).

## Non-goals

- No change to the estimate, the 48 h forecast, the trend arrows or percentages, `src/model/`,
  `src/learning/`, `netlify/functions/`, the server version string (v39.6), `period=P7D`, the
  Content-Security-Policy, or the service worker config.
- In `src/estimation/` only `nws.js` changes, and only by deletion of the flood-category code.
- No new visible wording except the label `Next 24h`. No new warnings or features.
- The pinned text in `src/ui/great-falls-ui.js` is not touched.

### Item 2: the header cell is the tap target

- `src/ui/gauges-ui.js` header template: the two cells get a class,
  `<div class="col-info-cell" style="text-align:right;">Next 24h <button type="button" class="col-info" ...>i</button></div>`
  and the same for Basin. The button markup is unchanged (it stays the keyboard and screen-reader control).
- Delegated click handler on `#branches`: replace `const info = e.target.closest('.col-info');` with
  ```js
  const cell = e.target.closest('.col-info-cell');
  const info = cell ? cell.querySelector('.col-info') : null;
  ```
  The rest of that branch is unchanged (close all, open this one if it was closed, set `aria-expanded`, return).
- Document dismiss handler (`click` and `pointerdown`): a target inside `.col-info-cell` no longer
  dismisses (replace the `.col-info` test with `.col-info-cell`). Sequence on a phone: `pointerdown`
  on the label (inside the cell, so no dismiss), then `click` (toggle).
- `src/styles/main.css`: `.col-info-cell { cursor: pointer; }`. iOS Safari only sends a click for a tap
  on a non-interactive element when it has a pointer cursor or its own handler; the pointer cursor
  makes the delegated handler work there.
- Hover bubble: stays on the icon only (`.col-info:hover::after` inside `@media (hover: hover)`).
  Not extended to the cell.

### Item 3: flood-category requests

`src/estimation/nws.js`:
- `fetchNWSForecasts()` (line 48): delete `categoryPromises` (55-57); replace the paired
  `Promise.all` (58-61) with `const forecastResults = await Promise.all(forecastPromises);`; delete
  the "Apply flood categories" loop (63-68). Everything from "Apply forecasts to data" on is unchanged.
- Delete `fetchFloodCategory` and its comment and docstring (98-116).
- Docstring of `fetchNWSForecasts` (43-47) and the "Fetch forecasts and flood categories in
  parallel" comment: drop the flood-category wording.
- `fetchWithTimeout` stays imported (used by `fetchSingleNWSForecast`).

`src/data/fetch.js`: delete `getTrendText` (line 784 to the end of the function) and its docstring.
`getTrendData` and `applyTrendToElement` stay.

Effect: 17 fewer requests per refresh. `fetchNWSForecasts()` now resolves when the forecasts are in,
instead of waiting for the slower of forecasts and categories; anything awaiting it can only get
its result sooner.
