## 1. Goal

Today the server **stores, validates, learns on, and reports accuracy of the RAW model** (no EMA correction;
`predictedCFS` at scheduled-update.js:776 is the raw final), while the **user is shown the CORRECTED model**
(great-falls.js:466-468). Accuracy stats describe a model nobody sees; `flowBinMatch:false` is baked into the
committed characterization baseline. C1 makes the learned/validated/reported model the one the user sees,
without a feedback loop and without residual bias from where the correction is applied.

## 2. Decisions locked (with rationale)

| # | Decision | Choice | Why |
|---|----------|--------|-----|
| D1 | Where the correction is applied | **End-apply, unit gain**: `correctedFinal = rawFinalUnclipped − correction`, after ensemble, before only a final display ceiling guard | `d(corrected)/d(correction) = −1` at every flow. Pre-ensemble apply dilutes by `porWeight` (~0.60 at high flow) and the ceiling collapses it to ~0.13 → ~5–6% residual bias. **[audit: confirmed sound]** |
| D2 | What flow bins the correction (apply **and** learn) | **`getFlowBin(rawFinalUnclipped)`** (server) / **`getGFFlowBin(rawFinalUnclipped)`** (client) — post-ensemble, pre-ceiling, correction-free; identical via shared helper | apply-bin == learn-bin by construction. **[audit: confirmed]** |
| D3 | Learning target | **Learn EMA on `rawFinalUnclipped − actual`** | Correction-independent → `c* = E[raw − actual]`. No feedback (3 sims). **[audit: confirmed feedback-free]** |
| D4 | Headline accuracy | **Report `correctedFinal − actual`, prequentially** (correction frozen at prediction time in stored `predictedCFS`) | Describes what the user sees; no in-sample optimism. **[audit: confirmed]** |
| D5 | Ceiling vs learning | Store **unclipped** raw final as the learning target; ceiling is a **display-only guard on the corrected output** | The 120% LF ceiling uses LF at prediction time but validation compares LF ~6.5h later → clipping censors the EMA target. Learning on unclipped removes the censoring (no exclusion needed). |
| D6 | Writer | **Server (cron) is the sole prediction writer** | Removes the C12 contamination race into the single `pending` slot. **[audit: removal surface confirmed complete]** |
| D7 | Client/server parity scope | C1 unifies the **correction-application** layer (shared helper); full displayed==validated (ensemble parity) stays **C19** | Do not claim displayed==validated yet. |
| D8 | Empirical CI | **DEFER C2 + table re-derivation to v36.1.** v36.0 keeps the existing **symmetric half-width** band (great-falls.js:512-514), now naturally centered on the de-biased corrected estimate | **[audit]** The live table (`constants.js:90`) was generated by `error_distribution_v2_python.py`, which **already uses the production logistic EF weight** — my "static 0.35" premise was false. A symmetric band is bias-independent (width unchanged by subtracting a constant), so centering it on the corrected estimate introduces **no double-subtraction**. The asymmetric/sign fix + re-deriving on corrected residuals (correct v2 script, estimate-based binning, Python+R blind) is a separate analysis-verified release. |
| D9 | Bin migration | **No reset**, but **gate on a live-row pre-check** | **[audit]** Existing bins encode `E[(ceiling-CLIPPED raw) − actual]` keyed by `binOf(clipped raw)` (server clips at :767 then bins at :772) — exact only when the ceiling didn't bind. Pre-check a sample of `gf_correction_bin` rows + recent predictions for ceiling-bound frequency / bin-key drift **before** trusting transfer. |
| D10 | Flow-state learning gate | **DROPPED from v36.0** | **[audit]** As designed it reads PoR trend at validation time (~19h after the prediction's PoR reading → wrong water parcel) and skips overshoot cases → biases the rising bin optimistically. The misclassification problem is real but needs parcel-aligned state + a simulation; track separately. |

**Expected user-visible effect at deploy:** displayed estimate steps **down** by ~`efWeight × correction` at
moderate/high flow (the previously-diluted portion now fully applied) — the bias being removed. Document in
CHANGELOG; one-time graph discontinuity self-heals in 24h.

## 3. Canonical corrected pipeline (both client and server)

```
porEstimateCFS = timeShiftedPoR + tributaries + PoR-delta        // correction-free (unchanged)
efWeight       = getEFWeight(porEstimateCFS)                      // from UNCORRECTED estimate
rawFinalUnclipped = ensemble(porEstimateCFS, EF, efWeight) or porEstimateCFS   // post-ensemble, pre-ceiling
flowState      = getFlowState(...)                               // per side (C19 owns selection parity)

// ---- shared helper: applyGFCorrection({rawFinalUnclipped, lfCFS, correctionBins, flowState}) ----
flowBin               = getFlowBin / getGFFlowBin (rawFinalUnclipped)         // D2
correction            = getGFCorrection(correctionBins, flowBin, flowState)   // pure, shared
correctedFinalUnclipped = rawFinalUnclipped − correction         // D1 unit gain
correctedFinal        = (lfCFS > 0 && correctedFinalUnclipped > CEILING_RATIO*lfCFS)
                          ? CEILING_RATIO*lfCFS : correctedFinalUnclipped     // D5 display guard
ceilingApplied        = (clipped)
// returns { flowBin, correction, correctedFinalUnclipped, correctedFinal, ceilingApplied }

// outputs:
predictedCFS   = round(correctedFinal)            // displayed + headline-scored
rawFinalCFS    = round(rawFinalUnclipped)          // CFS learning target (D3)
predictedStage = round2(estimateLFStage(correctedFinal))      // display
rawFinalStage  = round2(estimateLFStage(rawFinalUnclipped))   // stage learning target [audit]
correctionApplied = round(correction)
```

On the **server** `getEFWeight`/discrepancy guard already use the uncorrected `porEstimateCFS`
(scheduled-update.js:743,747) — no change. On the **client** they currently use the *corrected* estimate
(great-falls.js:476,478); end-apply removes the pre-ensemble subtraction, so the client switches to gating on
the uncorrected estimate (a parity fix for free).
